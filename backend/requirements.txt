# Emergency Blood Donor Alert System

When someone needs blood urgently, this app finds compatible, eligible donors nearby and alerts them by email. Donors accept with one click, and only then does the requester see the donor's phone number.

## Why
Existing tools (e-RaktKosh, Friends2Support) mostly give a search-and-call list. This app pushes alerts to the nearest eligible donors and widens the search automatically if nobody responds.

## Features
- JWT registration and login with donor / requester roles
- Blood group compatibility and 3-month donation gap filtering
- Distance-based matching (Haversine) with nearest donors first
- Wave-based email alerts: 5 donors, then 20 km, then 30 km if nobody accepts
- One-click Accept / Decline links; first acceptance closes the request
- Phone number shared only after acceptance
- Live request status and an OpenStreetMap (Leaflet) map with approximate donor locations

## Tech stack
React (Vite), Leaflet | FastAPI, SQLAlchemy | MySQL | JWT | Docker Compose | Jenkins | pytest

## Architecture
React frontend -> FastAPI backend -> MySQL, with email alerts sent from the backend.
Jenkins pipeline: build backend image -> run 9 pytest tests -> build frontend image -> deploy with Docker Compose -> smoke test.

## Run it
```
docker compose up --build
docker compose exec backend python seed.py
```
Open http://localhost:5173. Without SMTP settings, alert emails print in the backend logs.

## Limitations / future work
- Pending alert waves are held in memory and are lost if the server restarts (a job queue like Celery would fix this)
- Coordinates are typed or filled by the "use my location" button; a place search and map picker would help in emergencies
- Demo donors are synthetic data
